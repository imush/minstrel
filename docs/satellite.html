Running a satellite

Only for homes that cannot open a port. Most people never need one.

A minstrel-satellite is a small relay with a public address. A launchpad connects out to it and keeps the line open, so the app can reach a home that has no forwarded port — behind carrier-grade NAT, say, or a router nobody wants to touch.

It carries traffic, not trust. The connection stays encrypted end to end between the app and the launchpad; the relay routes by SNI without terminating TLS, so it holds no keys and cannot read or change your music. It sees which home the bytes are for, how many, and when.

One satellite serves many homes, so a family or a group of friends usually needs one between them. If you only want to use someone else's, you do not need this page — see joining a satellite instead.

It is a fallback, not the route

The app races every address it knows for a home and takes the first that answers, giving the direct ones a head start of about a second and a half. At home the local address wins; away from home, a working forwarded port normally wins too. The satellite is used when nothing direct answers in that time, or fails outright.

So a home that can open a port sends almost nothing through the relay — just an idle connection held open, a few bytes an hour. Only homes with no way in, behind carrier-grade NAT or an untouchable router, push their music through it. That is worth knowing before you size the hosting: ten homes on a satellite does not mean ten homes' worth of traffic.

1. Run it in Docker

The quickest way, on any VM with a public address:

docker run -d --name satellite --restart unless-stopped \
  -p 443:443 -v /srv/satellite:/data \
  -e SATELLITE_DOMAIN=sat.example.org \
  imush/minstrel-satellite:latest

Built for amd64 and arm64. The container binds 443 itself, which saves the redirect a plain binary needs for a privileged port. Give /data a path you choose: it holds the relay's key and the list of homes, and an unnamed volume is replaced when the container is recreated — which invalidates every invitation.

There is a docker-compose.yml in the repository with the rate limits ready to uncomment.

2. Point DNS at it

Each home is reached as <id>.<domain>, so the satellite needs its own name and a wildcard under it:

sat.example.org.     A     203.0.113.10
*.sat.example.org.   A     203.0.113.10
(and AAAA records, if the VM has IPv6)

Miss the wildcard and the satellite starts cleanly, accepts an invitation, and then quietly fails to route — so it is worth checking first.

With no domain of your own, use nip.io: it resolves anything.203-0-113-10.nip.io to that address, wildcard included, free. For 203.0.113.10 set SATELLITE_DOMAIN=sat.203-0-113-10.nip.io. Good enough to try it; a name you control is better for anything lasting, because then you can move the satellite without re-inviting every home.

3. Where to run it

Any VM with a public IPv4 address and TCP 443 reachable. One vCPU and 512 MB is plenty — the relay copies bytes and never decodes them.

Google Cloud

Compute Engine → an e2-micro in a region where it is covered by the always-free tier. Open the port, replacing satellite with the VM's network tag:

gcloud compute firewall-rules create satellite-443 \
  --allow tcp:443 --target-tags satellite --source-ranges 0.0.0.0/0

Reserve a static external address, or the IP changes when the VM restarts and every paired device loses the relay.

AWS

EC2 → a t4g.nano (arm64, cheapest) or t3.micro. Allow inbound TCP 443 from 0.0.0.0/0 in the security group, and attach an Elastic IP for the same reason. Lightsail is simpler and bundles transfer.

Anywhere else

Hetzner, OVH, Scaleway and most small hosts work the same way: create the VM, open 443, install Docker, run the command above.

A word on the bill

For the homes that do rely on it, this relay carries audio, and on the hyperscalers you pay for every byte leaving the machine. Google and AWS charge roughly $0.09–0.12/GB once the free allowance is gone, and an hour of lossless listening is about half a gigabyte. Hosts like Hetzner include tens of terabytes in the monthly price instead, which for this job is the difference between pennies and a surprise.

Either way, set the limits below before handing out invitations.

Without Docker: FreeBSD or Linux

One VM with only the satellite on it is the intended setup. Build it on any computer with Go:

git clone https://github.com/imush/minstrel-satellite && cd minstrel-satellite
GOOS=freebsd GOARCH=amd64 CGO_ENABLED=0 go build -o minstrel-satellite .

On FreeBSD, with the files from contrib/freebsd. It runs as its own unprivileged user on port 7443, and pf redirects 443 to it:

pw useradd satellite -d /nonexistent -s /usr/sbin/nologin
install -m 755 minstrel-satellite /usr/local/bin/
install -m 555 contrib/freebsd/satellite /usr/local/etc/rc.d/
sysrc satellite_enable=YES satellite_domain=sat.example.org
cp contrib/freebsd/pf.conf /etc/pf.conf      # check ext_if first
sysrc pf_enable=YES && service pf start
service satellite start

Its log is /var/log/satellite.log.

On Linux, build with GOOS=linux, copy the binary to /usr/local/bin, and run it under systemd as an unprivileged user. Port 443 needs either setcap 'cap_net_bind_service=+ep' on the binary, or a redirect from 443 to an unprivileged port with -port 443 so the satellite still advertises the public one.

4. Invite a home

One link per launchpad:

docker compose exec satellite minstrel-satellite invite -label "Lake house"

or, for a binary install, minstrel-satellite invite -data /var/db/satellite -label "Lake house".

Send the printed link to that home's owner, who pastes it into their launchpad console under Outside access → Satellite. It works once and is valid for a day. The link carries the satellite's key fingerprint, so a launchpad cannot be sent to an impostor.

Limits and housekeeping

For all homes or per home: -rate 4Mbit (top speed), -quota 100GB (data per month at full speed) and -over-rate 1Mbit (speed after that). In Docker these are SATELLITE_RATE, SATELLITE_QUOTA and SATELLITE_OVER_RATE.

At CD quality music needs about 1 Mbit/s; a compressed quality in the app's settings uses much less, which is worth telling the homes you invite.

minstrel-satellite homes lists the homes and their use this month, and remove drops one. All commands and options are in the README.

Back up the data directory. It holds the relay's key, and losing it means every home must be invited again.
